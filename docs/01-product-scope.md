# 01. 产品范围、七个页面与里程碑

## 1. 产品定位

PMO Portal 1.0 是**工具导航门户**，用户通过单一入口发现、搜索、收藏并打开已获授权的业务工具。第一版不是替代 SAP/SharePoint，也不是承诺完成完整流程引擎或多智能体平台。

## 2. 七大板块（可见 ≠ 已实现）

| 页面 | 首期 P0 | 后续 P1/P2 | 交互要求 |
|---|---|---|---|
| 首页总览 | 欢迎横幅、常用工具入口、公告 | 真实 KPI、待办统计 | 卡片和按钮有效；指标若为样例需标识 |
| 工具导航 | **核心**：搜索、类别、卡片、状态、入口、收藏 | 智能推荐、跨设备最近使用 | 不可用工具不能假装成功 |
| 流程中心 | 已批准外部流程的链接 / 建设中 | 真实审批与状态跟踪 | 未上线按钮说明原因 |
| 数据看板 | 静态布局、真实能取得的少量统计 | 项目/流程/节省工时看板 | 演示数值明示虚构 |
| 文件中心 | SharePoint 入口/模板入口 | 文件搜索、受权预览 | 原文件访问由目标系统鉴权 |
| AI 助手 | 已批准工具入口；受控示例 | RAG、MCP、Agent | 首版不默认启用自主操作 |
| 系统设置 | 只读个人信息、版本、维护说明 | 在线工具管理、角色管理 | 设置权限在服务端落实 |

## 3. 真实价值闭环

**登录 → 首页 → 搜索「RFQ」→ 打开工具 → 完成一项获批示例操作 → 返回门户。**

至少一个工具必须能从非开发者电脑访问；如果只是离线桌面程序，则展示可信的使用说明/安装入口，而非伪造网页地址。

## 4. 里程碑，不绑定未经确认的完成日期

- **M0：工程可启动。** 私有开发仓库、两人 Write、目录结构、基础 API、七个路由壳、发布可行性确认。
- **M1：工具导航可用。** 统一视觉、工具 API、搜索/分类/收藏、一个真实可访问工具入口。
- **M2：部署试用。** App Service、企业授权登录、手动或自动部署、日志和回滚。
- **M3：演示验收。** 非开发者用浏览器完成闭环；问题记录；确定下一批工具。

## 5. Go/No-Go 验收

- [ ] 企业授权员工能登录，非授权用户被拒绝。
- [ ] 首页/工具导航可用，其余板块状态真实。
- [ ] 至少一个经批准的工具可实际使用。
- [ ] 工具信息来自统一配置或接口，不是散落的硬编码。
- [ ] 能从固定 Git Commit 重建发布包；部署失败能回退。
- [ ] 不含密钥、客户数据、未经批准的外部依赖。
- [ ] 业务方确认页面上的入口和分类符合真实工作方式。

## 6. 3 分钟演示脚本

1. 展示企业登录和门户首页（30 秒）。
2. 进入工具中心，按类别筛选、关键词搜索、收藏（60 秒）。
3. 打开一个真正能用的业务工具，演示已获批准的样例流程（60 秒）。
4. 返回门户展示工具维护流程、版本和后续计划（30 秒）。

**红线：** 不把尚未实现的流程、虚构效率数字或未审批的 AI 能力包装成已经上线的实际功能。
