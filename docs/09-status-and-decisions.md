# 09. 决策记录、已知假设与待确认

最后更新：2026-11-17。这里记录的是**指导方案状态**，不是企业环境的事实证明。

## 已建议采用的决定

| ID | 决定 | 原因 |
|---|---|---|
| ADR-001 | 首版是工具导航门户 | 最快交付真实价值，避免功能无边界 |
| ADR-002 | React + TypeScript + Ant Design | 符合高保真桌面企业门户交互 |
| ADR-003 | Python FastAPI | 与现有 Python 工具技术一致、实现 API 快 |
| ADR-004 | 单个 Linux App Service 部署门户 | 降低费用、环境和部署复杂度 |
| ADR-005 | 模块化单体 + 独立业务工具入口 | 不强制重写原有应用 |
| ADR-006 | 工具配置文件起步 | 不为导航目录提前建大型数据库 |
| ADR-007 | 无批准不启用自主 Agent/MCP 编排 | 企业合规边界必须优先确认 |
| ADR-008 | 功能分支 + PR + 同伴审查 | 降低两人及 AI 修改冲突 |

## 当前须通过事实验证的项目

- [ ] 企业私有工程仓库与权限：双方能 clone、push、review、merge。
- [ ] 企业允许使用的 Python/Node/npm/PyPI 包来源。
- [ ] Azure App Service 资源、运行时、区域和预算已获批。
- [ ] GitHub Actions Runner 是否实际可运行；否则按批准的手动发布通道。
- [ ] Entra 试用用户分组、登录策略和授权。
- [ ] 第一个可接入工具的正确 URL、可访问范围及使用方法（只记录在受限环境）。
- [ ] 内部模型和第三方 Agent/MCP 的授权范围。
- [ ] 实际业务数据能否进入所选云端资源。

## 风险日志模板

| 风险 | 触发条件 | 缓解方案 |
|---|---|---|
| Runner 不可用 | 工作流排队或策略阻止 | 使用经批准的手动 ZIP 发布；申请授权 Runner |
| 企业认证进展慢 | 试用人员无法正确登录 | 测试环境先演示；不绕过正式鉴权 |
| Linux 兼容问题 | Windows 专属路径/依赖 | 路径抽象、运行时验证、日志排查 |
| 两人代码冲突 | 同时修改共享文件 | 接口先定、短分支、小 PR |
| 视觉与功能脱节 | 大量未响应按钮 | 明确状态、保证最少真实闭环 |

## 如何更新本仓库

只更新经批准可公开的方向性决定、接口示例、抽象状态和经验教训。实际环境变更的资源名、用户身份、网络拓扑、账单及权限详情留在企业内部平台。
