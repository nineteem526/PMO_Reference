# 07. 企业集成、身份、数据与 AI 安全

## “系统集成”不是所有系统都重写 MCP

- 确定性业务动作，例如读取已授权的文件目录、查询部署状态：优先使用企业允许的 REST API / SDK / Microsoft Graph。
- 只有需要 AI 自行发现、选择工具时，才考虑 MCP Client + 获批的 MCP Server。
- 使用 MCP 协议**不自动等于 Agent**；但模型自主规划与反复调用工具具有 Agent 特征，企业政策可能单独限制。
- 自研 Agent 即使藏在普通 Web 页面后端，也不能视为自动获准。

## 首版集成策略

| 能力 | 首版 | 后续可选 |
|---|---|---|
| GitHub | 软件工程协作；门户可仅展示版本字段 | 通过获批 GitHub App / API 查看发布信息 |
| Azure | 托管 PMO Portal | 最小权限 SDK 读取监控/状态 |
| SharePoint | 跳转到已授权文件库 | 经批准使用 Microsoft Graph 搜索/读取 |
| Power Automate | 跳转既有流程入口 | 经批准调用已有流程触发点 |
| RFQ | 点击进入获授权的现有工具 | 按数据分类、项目隔离规则做深度集成 |
| AI | 合规工具入口 / 受控演示 | 内部模型 + 审计 + 工具白名单 + 人工确认 |

## 登录与权限（两层）

1. **门户入口认证：** Entra/App Service Authentication 要求登录，并限制可访问的人员/组。
2. **业务授权：** 后端控制 API、工具访问；被打开的 SharePoint/RFQ 目标系统继续各自判断权限。

“能看到工具卡片”不应被视为拥有访问数据或调用该工具的权限。

## 网络方向

- 员工 → App Service：入站 HTTPS，企业要求时通过限制访问 / Private Endpoint 保护。
- App Service → 企业内部 API：出站可能需要批准的 VNet Integration 和到企业网络的合法连接。应用部署成功并不证明内部 API 可达。
- 不自行设置未经批准的 VPN、网关、代理或隐藏端口。

## 公开参考仓库注意事项

这个仓库的任何内容都对互联网可见。不要向其提交：真实域名/IP、账号、内部 API 路径、密钥、Token、真实错误响应、完整业务逻辑源码、RFQ 客户数据、未经授权的架构图、受限安全策略或截图。需求和问题只放**审查后的抽象描述**。严禁把“当前未被拦截”当作获得企业授权的证明。

## 生产前安全核验

- [ ] 试用人员白名单/分组确实生效。
- [ ] API 不会因前端隐藏按钮而失去授权校验。
- [ ] 所有真实业务 URL 和服务凭据只在企业批准环境存储。
- [ ] 最小权限原则、日志记录、异常处理和资源预算落实。
- [ ] 未授权的自研 Agent/MCP Server 不在生产环境执行。
